<a id="1-系统概述与商业运营定位"></a>
## 1. 系统概述与商业/运营定位

### 1.1 项目背景
**食刻 (ShiKe)** 是一款结合了 **“AI 视觉拍照识别”** 的极简热量追踪工具与 **“熟人私密对赌”** 社交契约机制的健康生活小程序。项目核心特色在于：**记录零摩擦、视觉极致美感、对赌真实刺激、烹饪油水可校准**。

### 1.2 后台运维系统核心定位
**食刻后台运维与数据管理系统 (ShiKe Admin Management System)** 是保障食刻小程序稳定高效运行的“大脑神经中枢”。系统兼具**技术运维监控**与**业务运营管控**双重职责：
- **AI 成本与配额审计**：实时监控多模态视觉大模型（GPT-4o-mini / 通义千问 Qwen-VL / 智谱 GLM-4V）的调用频次、每日每人 10 次的配额限制，以及 API 预估消耗费用。
- **用户全景履历档案**：穿透管理用户的生理指标（身高、体重、BMR、TDEE）、契约积分、每日膳食三大营养素及运动/饮水打卡。
- **社交对赌风控与干预**：实时监管各减脂战队的打卡进度与押金积分流转，支持运维一键解散作弊小队、强制结算或重新激活。
- **数据合规导出**：提供全量用户档案与膳食打卡记录的 UTF-8 BOM CSV 导出功能，服务于线下深度复盘与运营分析。

### 1.3 UI 设计哲学
界面采用 **Modern Dark Glassmorphism（深色高质感玻璃拟态）** 风格：
- 主色调以深空灰 (`#0F172A`, `#1E293B`) 搭配翡翠绿 (`#10B981`) 核心亮色。
- 高保真响应式布局，整合数据卡片 (KPI Metrics Grid)、柱状趋势图 (Bar Chart)、抽屉弹窗 (Drawer Modal) 与高清 Lightbox 原图预览。

<a id="3-安全鉴权与访问控制"></a>
## 3. 安全鉴权与访问控制 (Security & Auth)

### 3.1 鉴权架构设计
为了防止未授权人员越权访问后台关键 API 与泄露用户个人健康隐私数据，系统实现了轻量级基于 Token 的安全拦截防护机制：
1. **拦截器机制**：`AdminAuthInterceptor` 实现 `HandlerInterceptor` 接口。
2. **拦截路径规则**：
   - 拦截路径：`/api/v1/admin/**`
   - 放行路径：`/admin/index.html`（静态页面）、`/api/v1/admin/login`（登录接口）。
3. **Token 校验机制**：
   - 优先检查请求头 `Authorization: Bearer <token>`。
   - 备用检查 URL Query 参数 `?token=<token>`（专用于 CSV 导出下载场景）。
   - 在 Redis 校验 Key `shike:admin:token:<token>` 是否有效；离线状态自动兜底校验 `shike-admin-*` 格式。

### 3.2 认证流转示意
```
[未登录用户] ── 访问 /api/v1/admin/stats ──► [AdminAuthInterceptor] ── 返回 401 ──► [前端弹出 Login Modal]
                                                                                            │
[输入 admin / shike123456] ◄── 提交表单 ◄────────────────────────────────────────────────────┘
          │
          ▼
 [POST /api/v1/admin/login] ── 校验成功 ──► [生成 UUID Token, 存入 Redis 24h] ──► [返回 Token 给前端]
                                                                                            │
 [保存 Token 至 localStorage] ◄─────────────────────────────────────────────────────────────┘
          │
          ▼
 [以 Authorization: Bearer <token> 重新请求 API] ──► [验证通过, 正常加载大盘]
```

<a id="4-运维管理核心功能模块明细"></a>
## 4. 运维管理核心功能模块明细

### 4.1 大盘 KPI 核心指标看板 (Metrics Board)
后端通过 `AdminServiceImpl.getDashboardStats()` 实时聚合以下 7 大核心 KPI：

1. **注册用户总量 (`totalUsers`)**：调用 `userRepository.count()`，实时统计全量注册用户基数。
2. **今日新增注册 (`todayNewUsers`)**：过滤当日 `createdAt` 匹配的用户数。
3. **今日 AI 识别总次数 (`todayAiRecognitions`)**：扫描聚合 Redis `shike:ai:limit:*:{today}` 的所有用户使用量。
4. **预估 AI API 消耗成本 (`estimatedAiCost`)**：基于近 7 天累计 AI 调用频次，按多模态 Vision 模型标准价格（预估 0.02 元/次）自动计算。
5. **今日用户活跃度 (DAU - `todayActiveUsers`)**：
   - **5 维触点交叉去重算法**：取“今日注册/更新用户”、“今日饮食打卡用户”、“今日运动打卡用户”、“今日饮水用户”、“今日小队打卡用户”及“今日 Redis AI 调用用户 OpenID”的 Set 合集，确保 DAU 极其精准。
6. **活跃减脂小队 (`activeTeams`)**：统计 `status = 'ACTIVE'` 且成员数大于 0 的战队数。
7. **总契约积分池 (`totalPoints`)**：全量用户当前持有的契约积分总和。

### 4.2 AI 7 天频次趋势与成本分析 (AI Analytics)
大盘中集成【近 7 天 AI 拍照识别频次趋势图】：
- 动态获取过去 7 天每天的 AI 调用次数。
- 前端自动计算 7 天最高值作为基准，渲染自适应柱状图 (Bar Chart)。
- 当 Redis 缓存失效时，自动静默降级为统计当天的数据库饮食打卡记录数。

### 4.3 全量用户档案管理与三维履历穿透 (User Management)
- **实时搜索**：支持在 `searchInput` 中输入用户昵称、用户 ID 或微信 OpenID 进行秒级前端过滤。
- **用户基本信息**：展示头像、昵称、性别、年龄、身高、体重。
- **代谢卡路里模型**：展示 BMR 基础代谢率、TDEE 每日总能量消耗、目标减脂卡路里预算。
- **AI 配额监控**：实时展示该用户今日 AI 已用次数（如 `3 / 10 次`）；达到 10 次上限自动标红警示 (`limit-reached`)。
- **三维履历 Modal 抽屉**：点击【使用明细】按钮展开抽屉：
  - 🍽️ **饮食打卡 Tab**：查看历史餐别（早餐/午餐/晚餐/加餐）、卡路里、三大营养素（碳水/蛋白质/脂肪）、餐品拆解明细及 AI 拍照图片。
  - 🏃 **运动与水份 Tab**：查看运动项目、消耗卡路里以及每日饮水量日志。
  - 🏆 **小队契约打卡 Tab**：查看该用户参与的所有减脂战队的打卡成功/失败记录。

### 4.4 减脂对赌小队运维与硬核干预 (Team Operations)
运维人员可点击顶部【查看减脂小队与成员】或大盘【活跃减脂小队】卡片，弹窗管理小队：
- **小队看板筛选**：支持【全部小队】、【🔥 进行中】、【🏁 已结赛】三态切换与搜索。
- **战队全景元数据**：展示战队 ID、战队名称、邀请码、队长信息、目标打卡天数、已进行天数、个人保证金积分及创建时间。
- **战队成员穿透**：明细展示队长/队员标识、今日打卡状态（系统自动比对用户今日摄入热量与目标卡路里预算）、累计成功打卡天数、积分余额及加入时间。
- **硬核干预操作**：
  - `DISBANDED`（解散小队）：当战队涉嫌刷分或非法作弊时，运维人员可直接强制解散。
  - `FAILED`（标记结算）：提前结束战队并触发结算流程。
  - `ACTIVE`（重新激活）：误操作后的恢复机制。

### 4.5 智能图像防断链与 Lightbox 大图预览
- **多级 URL 解析器 (`resolveAvatarUrl`)**：
  - 处理微信 `qlogo` 默认头像。
  - 自动修复本地临时文件 `tmp` 路径为默认优雅 fallback 图。
  - 自动为服务端 `/uploads/food_xxx.jpg` 补充完整 API 前缀 `/api/v1/uploads/`。
- **高清大图 Lightbox 模态框**：点击用户头像或餐品解析照片，可在暗色悬浮框中放大预览原图，并支持在新标签页独立打开。

### 4.6 运营数据一键 CSV 导出 (Data CSV Exporter)
页面顶部提供两个绿色与紫色一键导出按钮：
1. **导出全量用户 CSV (`exportCsv('users')`)**：导出全量用户的 ID、OpenID、昵称、性别、年龄、身高、体重、BMR、TDEE、目标摄入、契约积分及注册时间。
2. **导出饮食明细 CSV (`exportCsv('diets')`)**：导出全量饮食打卡记录 ID、打卡日期、用户 ID、餐别、总热量、三大营养素及餐品解析明细。
- **防乱码机制**：后端导出方法前置写入 `\uFEFF` (UTF-8 BOM)，使用 Excel 打开时中文绝不乱码。

<a id="5-后台-rest-api-接口规范明细"></a>
## 5. 后台 REST API 接口规范明细

通用基础路径：`/api/v1/admin`  
所有需鉴权接口需在 Header 附带：`Authorization: Bearer <token>`

### 5.1 管理员登录认证
- **接口路径**：`POST /api/v1/admin/login`
- **请求体 (JSON)**：
  ```json
  {
    "username": "admin",
    "password": "shike123456"
  }
  ```
- **响应示例 (JSON)**：
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {
      "username": "admin",
      "token": "shike-admin-a1b2c3d4e5f67890",
      "adminName": "超级管理员"
    }
  }
  ```

### 5.2 检查鉴权状态
- **接口路径**：`GET /api/v1/admin/check-auth`
- **响应示例**：
  ```json
  { "code": 200, "message": "success", "data": "Authenticated" }
  ```

### 5.3 获取大盘 KPI 统计与 7 天 AI 趋势
- **接口路径**：`GET /api/v1/admin/stats`
- **响应示例 (JSON)**：
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {
      "totalUsers": 158,
      "todayNewUsers": 12,
      "todayAiRecognitions": 45,
      "todayDietRecords": 68,
      "todayActiveUsers": 38,
      "activeTeams": 6,
      "totalPoints": 24500,
      "estimatedAiCost": 0.90,
      "aiTrend": [
        { "date": "07-29", "count": 20 },
        { "date": "07-30", "count": 32 },
        { "date": "07-31", "count": 28 },
        { "date": "08-01", "count": 40 },
        { "date": "08-02", "count": 35 },
        { "date": "08-03", "count": 50 },
        { "date": "08-04", "count": 45 }
      ]
    }
  }
  ```

### 5.4 获取全量用户列表
- **接口路径**：`GET /api/v1/admin/users`
- **响应示例**：返回用户基本信息、今日 AI 已用次数、累计膳食打卡数、累计运动打卡数。

### 5.5 获取指定用户三维履历明细
- **接口路径**：`GET /api/v1/admin/users/{userId}/records`
- **响应示例**：包含 User 对象、`dietRecords` 列表、`exerciseRecords` 列表、`waterRecords` 列表及 `teamCheckins` 列表。

### 5.6 获取全量减脂小队与成员列表
- **接口路径**：`GET /api/v1/admin/teams`
- **响应示例**：返回全量小队元数据及小队成员明细数组。

### 5.7 修改小队运行状态
- **接口路径**：`POST /api/v1/admin/teams/{teamId}/status?status={newStatus}`
- **参数说明**：`newStatus` 可选值：`ACTIVE`, `FAILED`, `DISBANDED`。

### 5.8 导出数据 CSV
- **接口路径**：
  - 用户 CSV：`GET /api/v1/admin/export/users?token={token}`
  - 饮食 CSV：`GET /api/v1/admin/export/diets?token={token}`
- **响应类型**：`text/csv;charset=UTF-8` 文件流下载。

<a id="7-运维操作-sop-与常见场景处置"></a>
## 7. 运维操作 SOP 与常见场景处置

### 场景 1：发现战队恶意刷积分或偷吃作弊
1. 在顶部搜索框搜索战队名称或队长昵称。
2. 点击战队卡片展开成员穿透列表，检查成员的【今日摄入总热量】是否异常超标或空打卡。
3. 点击右侧【解散小队】按钮，在弹出的确认框中确认。
4. 战队状态将立即被更新为 `DISBANDED`，阻止作弊者在深夜清盘时瓜分保证金。

### 场景 2：用户反馈“AI 拍照打卡提示超限/故障”
1. 运维人员在全量用户列表中搜索该用户的 ID 或昵称。
2. 查看【今日 AI 使用次数】字段。若显示 `10 / 10 次`，说明用户触碰了每日 10 次防刷频限额。告知用户次日零点自动重置。
3. 若次数未满但仍然报错，检查后台 Redis 连接状态与 OpenAI 兼容 API 密钥额度。

### 场景 3：导出全量数据用于周度运营复盘
1. 确保已登录运维后台。
2. 点击页面顶部的【导出用户 CSV】与【导出饮食明细 CSV】按钮。

## 8. 系统部署与运行构建指南

### 8.1 本地编译与启动
前置环境要求：JDK 17、Maven 3.8+、MySQL 8.0、Redis 6.x。

```powershell
# 1. 进入后端项目目录
cd d:\heming\shike\shike-backend

# 2. 设置 JDK 17 环境变量 (Windows)
$env:JAVA_HOME="D:\Program Files\Java\jdk17"

# 3. 编译构建 JAR 包
mvn clean package -DskipTests

# 4. 运行后端服务
java -jar target/shike-backend-1.0.0.jar
```

<a id="9-高级运营管控与安全审计拓展体系"></a>
## 9. 高级运营管控与安全审计拓展体系 (v2.0 升级)

为应对复杂的运营环境与精细化数据分析需求，系统于 2026-08-04 升级接入 5 大核心运营调控工具：

### 9.1 用户账号状态管控 (封禁 / 解封)
- **业务逻辑**：在 `tb_user` 表中引入 `status` 状态字段（`ENABLED` / `DISABLED`）。后台管理员可在全量用户列表中一键对违规/刷接口账号执行封禁。
- **安全拦截**：被封禁的账号在访问小程序接口时触发 `403 Forbidden` 拦截，提示“账号已被冻结/禁用，请联系客服”。

### 9.2 动态 AI 次数限额管理
- **分布式配置**：通过 Redis 动态调控键 `shike:sys:config:ai_daily_limit`（默认 10 次）和特定用户 VIP 额度 `shike:sys:config:user_ai_limit:{userId}`。
- **在线提配**：支持管理员在后台在线调高全局默认 AI 调用频次上限，或针对特权用户在用户明细弹窗中一键增加其每日 AI 专属额度。

### 9.3 积分增扣与变动流水
- **流水表 `tb_point_log`**：详细记录每一次积分增扣的 `userId`、`amount` (正负变动值)、`type` (如 `ADMIN_ADJUST`, `TEAM_CHECKIN`)、`remark` 及 `createdAt`。
- **管理员变动**：管理员可在用户列表中直接点击「调整积分」，在弹窗中选择增加/扣除积分并附带日志备注，消费记录实时写入流水账单。

### 9.4 用户留存率分析 (Cohort 次留 / 7留趋势看板)
- **留存 Cohort 算法**：基于用户注册日期，统计该批次用户在注册后第 +1 天（次日留存）与第 +7 天（7日留存）在饮食/运动/打卡/AI识别中的综合活跃度。
- **可视化看板**：Dashboard KPI 区域集成「用户留存分析」可点击卡片，点击弹出高保真弹窗展示近 7-14 天留存率柱状趋势与数据表。

### 9.5 管理员操作审计日志 (RBAC 审计体系)
- **审计表 `tb_admin_audit_log`**：记录管理员所有敏感调控动作（`adminUsername`, `action`, `target`, `details`, `ip`, `createdAt`）。
- **监控弹窗**：系统顶部导航增加「安全审计日志」入口，随时调阅谁封禁了账号、谁调整了积分、谁修改了全局 AI 配额等关键轨迹。

### 9.6 每日活跃用户 (DAU) 管理列表
- **功能特性**：在全量用户管理列表上方新增动态 Filter Chips（包含 `全部用户`, `🔥 今日活跃用户 (DAU)`, `🚫 已封禁用户`）。
- **实时穿透**：点击 `🔥 今日活跃用户 (DAU)` 选单，列表将毫秒级过滤并仅呈现今日产生饮食/运动/饮水/打卡/AI识别记录的活体用户，并在用户昵称右侧附带高亮 `🔥 今日活跃` 识别 Badge。
