# 食刻宠物养成系统功能方案

更新时间：2026-08-18

## 1. 功能定位

宠物养成系统不是独立小游戏，而是食刻减脂打卡体系里的“情绪激励层”。

核心目标：

- 提高用户每日回访和打卡意愿。
- 把运动、饮食、饮水等健康行为转化为即时奖励。
- 让用户从“被迫自律”变成“为了照顾自己的自律搭子而行动”。
- 为后续短视频内容和产品传播提供更强记忆点。

一句话定位：

> 完成运动，投喂你的自律搭子。它会陪你一起变轻、变好、变强。

## 2. 核心创意

用户可以在小程序里拥有一只专属宠物。宠物的成长与用户健康行为绑定：

- 用户完成运动打卡，获得宠物食物。
- 用户投喂宠物，宠物获得饱食度、亲密度和成长值。
- 连续打卡可以推动宠物升级、解锁表情、姿态或装扮。
- 用户可以通过上传图片或输入描述，生成宠物初始长相。

传播钩子：

> 我不运动，它就没饭吃。

这个钩子适合用于抖音、小红书、视频号等内容平台，能够把减脂行为变成更轻松、更有情绪连接的故事。

## 3. MVP 功能范围

第一版建议只做最小可上线版本，避免把减脂主线拖成复杂游戏系统。

MVP 必做功能：

1. 创建宠物
2. 上传参考图或填写描述生成宠物头像
3. 每日运动打卡
4. 运动打卡后获得 1 份食物
5. 投喂宠物
6. 宠物增加经验、亲密度、饱食度
7. 展示等级、成长进度、今日是否已投喂

MVP 暂不做：

- 宠物商城
- 复杂换装
- 宠物社交
- 战斗系统
- 繁殖系统
- 多宠物切换
- 高成本实时动画

## 4. 用户流程

```text
进入宠物页
→ 未创建宠物时展示创建入口
→ 选择宠物风格或上传参考图
→ AI 生成宠物形象
→ 用户命名宠物
→ 每天完成运动打卡
→ 获得食物
→ 投喂宠物
→ 宠物成长值增加
→ 连续打卡解锁阶段奖励
```

## 5. 宠物创建流程

创建入口：

- 首页卡片入口：“领养你的自律搭子”
- 底部 Tab 入口：“搭子”
- 运动打卡后弹窗引导：“今天运动完成，要不要领养一个自律搭子？”

创建步骤：

1. 选择基础类型

```text
猫系 / 狗系 / 小熊 / 毛绒怪 / 小龙 / 水母 / 随机
```

2. 选择生成方式

```text
上传参考图
输入描述
随机生成
```

3. AI 生成宠物头像

4. 用户确认或重新生成

5. 给宠物命名

默认命名候选：

```text
卡卡 / 小燃 / 饭团 / 豆豆 / 自律搭子
```

## 6. AI 生成宠物长相

### 6.1 输入

用户可以上传：

- 自己喜欢的宠物照片
- 玩偶照片
- 喜欢的颜色参考
- 食物、杯子、生活物件等非人物参考图

安全限制：

- 不建议使用真人脸生成宠物。
- 如果检测到人脸，应提示用户：“建议上传宠物、玩偶或物品作为参考，这样生成效果更稳定。”

### 6.2 生成提示词模板

```text
请基于用户上传的参考图，生成一个原创的可爱电子宠物形象。

要求：
- 不生成真人脸
- 不复刻版权角色
- 保留参考图的主要颜色、气质和视觉特征
- 风格治愈、圆润、适合小程序宠物养成
- 正面半身或全身
- 适合作为头像和宠物主形象
- 背景干净，优先透明背景或浅色背景
- 不包含文字、水印、Logo
```

### 6.3 生成策略

第一版建议只生成一张主形象图：

```text
pet_image_url
```

后续升级时再扩展：

```text
happy_image_url
hungry_image_url
sleep_image_url
level_up_image_url
```

这样可以降低第一版成本和开发复杂度。

## 7. 运动打卡与投喂规则

第一版规则：

```text
用户每日完成运动打卡 → 获得 1 份普通食物
每天最多通过运动获得 1 份食物
投喂 1 份食物 → 饱食度 +30，经验 +10，亲密度 +5
```

运动打卡可以支持：

```text
快走
跑步
骑行
力量训练
跳绳
瑜伽
其他运动
```

运动记录字段：

```text
运动类型
运动时长
估算消耗
打卡日期
备注
```

后续可以扩展规则：

```text
喝水达标 → 额外获得小水滴道具
三餐完整记录 → 获得低卡零食
热量未超标 → 获得健康餐
连续 7 天运动 → 获得限定装饰
```

## 8. 宠物状态设计

宠物基础属性：

```text
level       等级
exp         成长值
fullness    饱食度
intimacy    亲密度
mood        心情
streak_days 连续陪伴天数
food_count  当前食物数量
```

心情状态：

```text
开心：今天已投喂
普通：今天未投喂，但饱食度正常
饿了：饱食度较低
想运动：今天还没有完成运动打卡
```

不建议设置“死亡”或强惩罚机制。减脂产品要减少用户失败羞耻感，宠物可以失落，但不要惩罚用户太重。

## 9. 成长规则

建议等级规则：

```text
每次投喂：exp +10
每级所需经验：level * 50
升级后：fullness +10，intimacy +5
```

阶段奖励：

```text
Level 1：幼年期
Level 5：解锁开心表情
Level 10：解锁运动头带
Level 15：解锁闪光背景
Level 20：成长为进阶形态
Level 30：完成第一阶段养成
```

连续打卡奖励：

```text
连续 3 天：奖励普通食物 x1
连续 7 天：奖励限定表情
连续 14 天：奖励装饰
连续 30 天：奖励进化形态或纪念海报
```

## 11. 后端数据结构建议

### 11.1 宠物表 tb_pet

```sql
CREATE TABLE tb_pet (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  name VARCHAR(50) NOT NULL,
  species VARCHAR(30) DEFAULT NULL,
  image_url VARCHAR(512) DEFAULT NULL,
  prompt TEXT DEFAULT NULL,
  level INT DEFAULT 1,
  exp INT DEFAULT 0,
  fullness INT DEFAULT 60,
  intimacy INT DEFAULT 0,
  mood VARCHAR(30) DEFAULT 'NORMAL',
  streak_days INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id)
);
```

### 11.2 宠物食物表 tb_pet_food

```sql
CREATE TABLE tb_pet_food (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  food_type VARCHAR(30) DEFAULT 'NORMAL',
  count INT DEFAULT 0,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_food_type (user_id, food_type)
);
```

### 11.3 宠物行为记录表 tb_pet_action

```sql
CREATE TABLE tb_pet_action (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  pet_id BIGINT NOT NULL,
  action_type VARCHAR(30) NOT NULL,
  value INT DEFAULT 0,
  action_date DATE NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_date (user_id, action_date),
  INDEX idx_pet_id (pet_id)
);
```

### 11.4 运动记录表 tb_exercise_record

```sql
CREATE TABLE tb_exercise_record (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  exercise_type VARCHAR(30) NOT NULL,
  duration_minutes INT DEFAULT 0,
  calories_burned DECIMAL(6,1) DEFAULT 0.0,
  record_date DATE NOT NULL,
  remark VARCHAR(255) DEFAULT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_date (user_id, record_date)
);
```

## 12. API 设计建议

```text
GET /pet/my
获取当前用户宠物

POST /pet/create
创建宠物

POST /pet/generate
上传参考图并生成宠物形象

POST /exercise/checkin
运动打卡

GET /exercise/today
获取今日运动打卡状态

POST /pet/feed
投喂宠物

GET /pet/today
获取今日宠物状态、食物数量、是否可投喂
```

### 12.1 POST /pet/create

请求：

```json
{
  "userId": 1,
  "name": "小燃",
  "species": "BLOB",
  "imageUrl": "https://example.com/pet.png",
  "prompt": "蓝色、圆润、像小水母"
}
```

响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "name": "小燃",
    "level": 1,
    "exp": 0,
    "fullness": 60,
    "intimacy": 0,
    "mood": "NORMAL"
  }
}
```

### 12.2 POST /exercise/checkin

请求：

```json
{
  "userId": 1,
  "exerciseType": "WALK",
  "durationMinutes": 30,
  "caloriesBurned": 180
}
```

业务逻辑：

```text
1. 写入运动记录
2. 判断今日是否首次运动打卡
3. 如果是首次，给用户普通食物 +1
4. 返回今日可投喂状态
```

### 12.3 POST /pet/feed

请求：

```json
{
  "userId": 1,
  "petId": 1,
  "foodType": "NORMAL"
}
```

业务逻辑：

```text
1. 校验食物数量是否足够
2. 扣除食物
3. fullness +30，最高 100
4. intimacy +5
5. exp +10
6. 判断是否升级
7. 写入 tb_pet_action
8. 返回最新宠物状态
```

## 15. 风险与注意事项

### 15.1 不要喧宾夺主

宠物是激励系统，不是主业务。食刻主线仍然是：

```text
饮食记录 → 热量预算 → 运动消耗 → 体重管理 → 习惯养成
```

### 15.2 避免过强惩罚

不要设计“宠物死亡”。如果用户断签，只做轻度提醒：

```text
它有点想你了，今天要不要动一动？
```

### 15.3 控制 AI 生成成本

第一版不要频繁生成图片。建议：

```text
首次创建免费生成 1 次
重新生成需要积分或限制次数
升级阶段优先用预设视觉资产
```

### 15.4 版权与安全

上传图生成宠物时，要避免：

- 明星脸
- 真人脸复刻
- 明确版权角色复刻
- 带 Logo 或商标的图像复刻

## 17. 结论

宠物养成系统值得做，但第一版必须克制。

建议先把它做成“运动打卡后的情绪奖励”：

```text
运动 → 获得食物 → 投喂宠物 → 宠物成长
```

这个闭环简单、清晰、容易上线，也适合内容传播。等验证用户喜欢后，再逐步扩展 AI 形象生成、装扮、进化、海报和社交展示。

## 18. 关键补充：防作弊与打卡可信度

宠物投喂和运动打卡绑定后，用户可能会为了快速获得食物而随意填写运动时长。因此第一版需要设计轻量防作弊，不要做得太重，但要避免明显刷奖励。

第一版校验规则：

```text
单次运动时长最短 5 分钟，低于 5 分钟不发放食物
单次运动时长最长 180 分钟，超过后进入人工限制或只按 180 分钟计算
每天通过运动最多获得 1 份食物
同一天重复提交运动记录，可以记录，但不重复发放食物
运动消耗热量如果由用户手填，只作为展示，不参与强奖励计算
```

后续增强方案：

```text
接入微信运动步数
允许用户上传运动截图作为辅助凭证
支持 Apple Health / 华为运动健康等第三方数据时，再提升奖励可信度
异常高频打卡进入风控队列
```

建议产品原则：

> 防作弊只保护奖励系统，不要让用户感觉自己被审判。

## 19. 隐私、授权与内容安全

宠物生成会涉及用户上传图片，因此需要补充隐私和内容安全设计。

上传前提示：

```text
建议上传宠物、玩偶、物品或颜色参考图。
请不要上传真人脸、身份证、病历、银行卡等敏感图片。
图片仅用于生成你的宠物形象。
```

需要在隐私政策中说明：

```text
收集内容：用户主动上传的图片、宠物名称、生成描述、运动打卡记录
使用目的：生成宠物形象、展示养成进度、提供运动投喂功能
保存周期：用户删除宠物或注销账号后删除相关数据
第三方处理：如果接入 AI 图片生成服务，需要说明图片会被提交给第三方模型服务处理
```

内容安全规则：

```text
检测真人脸、裸露、暴力、血腥、政治敏感、商标 Logo、明星照片等风险内容
高风险图片拒绝生成
中风险图片提示用户更换参考图
生成结果也需要做安全审核，避免输出不适合展示的图片
```

## 20. 提醒与召回策略

宠物系统最大的价值是召回用户，但提醒不能太烦。

建议第一版只做三类提醒：

```text
运动提醒：今天还没运动，你的自律搭子在等你
投喂提醒：运动完成啦，快去投喂它
连续陪伴提醒：你们已经连续陪伴 7 天了
```

提醒频率建议：

```text
每天最多 1 次主动提醒
用户可关闭提醒
连续 3 天未打开小程序后，减少提醒频率
不要使用“宠物快饿死了”等强负罪感文案
```

文案方向：

```text
它今天有点想你了，要不要去走 10 分钟？
运动完成，今天的食物已经准备好了。
你们已经连续陪伴 7 天，今天也别断呀。
```

## 21. 数据指标与上线验收

宠物系统是否值得继续做，不能只看主观感觉，要提前定义指标。

上线后重点观察：

```text
宠物创建率：进入宠物页的用户中，有多少完成创建
运动打卡率：有宠物用户的每日运动打卡比例
投喂转化率：获得食物后完成投喂的比例
次日留存：创建宠物后的次日回访
7 日留存：创建宠物后的 7 日回访
连续打卡天数：宠物用户 vs 非宠物用户对比
AI 生成成功率：生成成功 / 发起生成
AI 生成满意率：确认使用 / 生成成功
```

MVP 验收标准建议：

```text
宠物创建流程成功率 >= 80%
运动打卡后投喂转化率 >= 60%
有宠物用户 7 日留存高于无宠物用户
AI 生成失败率低于 10%
单用户 AI 生成平均成本可控
```

## 22. AI 成本与降级方案

AI 图片生成是最容易失控的成本点，需要从第一版就限制。

成本控制策略：

```text
新用户首次免费生成 1 次
重新生成需要消耗积分
每天最多重新生成 3 次
生成图片统一压缩并存储到对象存储
同一提示词和同一参考图可以做缓存
长期成长阶段优先使用预设装饰叠加，不每次重新生成整张图
```

降级方案：

```text
AI 服务不可用时，提供默认宠物模板
生成超时时，提示用户稍后查看结果
生成失败时，返还生成次数或积分
图片审核失败时，引导用户更换参考图
```

默认模板建议至少准备：

```text
绿色小燃兽
蓝色水滴兽
粉色饭团兽
黄色小熊兽
紫色毛绒怪
```

## 23. 边界情况与异常处理

需要提前覆盖以下场景：

```text
用户没有宠物却点击投喂：引导创建宠物
用户没有食物却点击投喂：引导完成运动打卡
用户今天已通过运动获得食物，再次打卡：只记录运动，不重复发食物
用户删除宠物：二次确认，并说明会清空宠物成长数据
用户重新生成宠物：保留等级和亲密度，只替换形象
宠物满级后继续投喂：继续增加亲密度，经验转为陪伴值
用户跨时区或日期变化：统一以服务器 Asia/Shanghai 日期为准
```

删除宠物提示文案：

```text
删除后将清空它的形象和成长记录，但不会影响你的饮食、运动和体重数据。确定删除吗？
```

## 24. 与现有业务的关系

宠物系统要和食刻已有模块形成闭环，而不是另起一套孤立玩法。

推荐绑定关系：

```text
首页：展示宠物今日状态小卡片，引导运动或投喂
饮食记录：三餐完整记录可作为后续额外奖励来源
饮水记录：饮水达标可获得小水滴道具
减脂对赌：队友可以看到彼此宠物等级，增强轻社交
个人档案：展示宠物陪伴天数和成就
历史记录：记录宠物投喂与运动打卡关联
```

第一版入口建议：

```text
首页增加一张“自律搭子”卡片
底部 Tab 是否新增宠物页，可以等 MVP 验证后再决定
```

如果底部 Tab 位不够，建议先不新增 Tab，而是在首页和个人档案提供入口。等宠物数据证明能提高留存，再升级为主入口。

## 25. 建议的开发顺序

为了降低风险，建议按下面顺序实现：

```text
第 1 步：先做不依赖 AI 的默认宠物模板
第 2 步：打通运动打卡 → 获得食物 → 投喂 → 升级
第 3 步：上线宠物页基础 UI 和首页入口
第 4 步：观察 7 天数据
第 5 步：再接入 AI 图片生成
第 6 步：做连续打卡奖励和分享海报
```

这样即使 AI 生成暂时没接好，宠物养成闭环也能先上线验证。

## 26. 全网爆款调研与体验升级完善方案（v2.1 增强）

基于 2026 年国内外自律与养成爆款产品（Finch、Habit-chi、Forest、体重小本等）的深度调研，我们在现有方案基础上补充以下 5 大核心体验升级点：

### 26.1 视觉风格三大主流方向与定位

1. **方向一：3D Q弹果冻 / 粘土潮玩风（Claymorphism / PopMart 风格）🔥 最推荐**
   - **视觉特征**：高光、圆润、Q弹微透、带有软胶潮玩手办质感。
   - **优势**：与《食刻》现有的翡翠绿水滴气泡、磨砂毛玻璃浅色画风 100% 天然契合，高级感与治愈感兼备。
2. **方向二：低饱和治愈手绘绘本风（Finch 风格）**
   - **视觉特征**：粗线条手绘轮廓、马卡龙温和色调、无公害萌物插画（如小水獭、小恐龙、小企鹅）。
   - **优势**：无防御感，适合作为 AI 生图风格分支或特定用户偏好。
3. **方向三：复古拓麻歌子像素风（Pixel Tamagotchi / 8-bit）**
   - **视觉特征**：点阵复古像素、怀旧电子宠物机质感。
   - **优势**：极度轻量，极客与怀旧感强。

### 26.2 五大核心体验升级规范

#### 1. 轻触互动反馈与打气台词库（微小情绪价值）
用户在宠物主页**轻触/点击宠物身体**时，触发轻微弹性缩放（`scale(0.92)`）与 Q 弹抖动，并随机弹出一条**治愈系/自律打气气泡台词**：
- **已投喂 / 开心状态**：
  - *“吃得饱饱，今天陪你一起燃脂！”*
  - *“本搭子宣布：你今天超自律！”*
  - *“今天又多消耗了卡路里，我们都在变强！”*
- **未运动 / 求投喂状态**：
  - *“咕噜噜～肚子好饿，快去运动带回鸡胸肉吧！”*
  - *“今天还没有动一动哦，去散个步我也能吃上饭啦～”*
- **深夜提醒状态（22:30 后）**：
  - *“早点睡哦，熬夜皮质醇升高会影响掉秤呢～”*
- **连续陪伴里程碑**：
  - *“哇！我们已经连续自律第 7 天啦，你变轻我也变帅了！”*

#### 2. 与食刻四大核心场景建立彩蛋联动
不仅绑定运动打卡，还为全站健康行为提供惊喜彩蛋：
- **💧 饮水水滴联动**：完成每日 2000ml 饮水达标，宠物头顶增加【水滴滋润光环】；

- **⚖️ 体重记录联动**：成功记录体重并达成掉秤，宠物触发庆祝撒花动作。
