## 1. 留存现状深度诊断与破局模型

### 1.1 核心留存漏斗瓶颈分析
健康饮食与热量控制类产品天然具备**“高摩擦、反人性”**特征。经过对《食刻》（咔嚓算卡）现有代码与用户行为链路的审计，发现用户从尝鲜到流失的 4 大断层：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    用户流失断层分析 (User Churn Breakdown)                   │
├───────────────────┬────────────────────────────┬────────────────────────────┤
│ 节点              │ 现状痛点                   │ 导致后果                   │
├───────────────────┼────────────────────────────┼────────────────────────────┤
│ 1. 首次使用       │ 签到藏在个人中心三级入口   │ 首页无打卡感知，次留极低   │
│ (Day 1)           │ 仅有固定+20分，无连击激励  │ 无连击概念，漏记无沉没成本 │
├───────────────────┼────────────────────────────┼────────────────────────────┤
│ 2. 核心社交体验   │ 5人对赌必须6位熟人邀请码   │ 80%+ 散客被门槛直接劝退   │
│ (Day 2 ~ Day 3)   │ 散客无法参与间谍/瓜分/道具 │ 沦为纯工具，新鲜感一过即抛 │
├───────────────────┼────────────────────────────┼────────────────────────────┤
│ 3. 习惯巩固期     │ 仅有单点饮水推送，缺少三餐 │ 小程序退出即被遗忘，缺乏   │
│ (Day 4 ~ Day 7)   │ 与夜间对赌结算的主动召回   │ 微信下拉常驻入口指引       │
├───────────────────┼────────────────────────────┼────────────────────────────┤
│ 4. 长期价值沉淀   │ 缺乏周度减脂数据汇总复盘   │ 用户感知不到“坚持一周瘦了” │
│ (Day 7+)          │ 历史卡路里仅为孤立流水     │ 沉没成本低，轻易卸载放弃   │
└───────────────────┴────────────────────────────┴────────────────────────────┘
```

### 模块一：首页「连续自律连击 (Streak Board)」与阶梯成长体系

#### 2.1 业务场景与交互设计
* **展示位置**：`pages/index/index` 首页核心看板上方黄金首屏，替代原孤立的静态信息条。
* **视觉呈现**：
  * **连击火苗胶囊**：`🔥 连续自律 5 天`（伴随呼吸微动效，金橙色渐变发光）。
  * **7 天进度轨道 (Streak Track)**：横向 7 个圆环节点，展示 Day 1 ~ Day 7：
    - 已完成天：绿色圆圈打勾 `✓`。
    - 今日待打卡：高亮黄色脉冲边框 `+50`。
    - 未到达天：灰色虚线圆圈。
    - 第 7 天终点：**金色神秘宝箱** 🎁。
* **积分经济学精算与阶梯奖励梯度表（平衡闭环模型）**：
  - **设计背景**：系统真实消耗为 AI 拍照识别（5分/次，日均10~15分）、膳食深度诊断（15分/次）、单人断签补卡（50分/次）、AI运动饮食定制大计划（100分/次）。为杜绝通胀、保障积分珍贵感，7天循环总赠送积分严格控制为 **128 积分**，实现“日常打卡保本微赚，关键节点给稀有道具与高光成就”：
  | 连续天数 | 积分奖励 | 特殊掉落奖励 | 经济学测算与心理设计 |
  | :--- | :--- | :--- | :--- |
  | **第 1 天** | **+5 pts** | 无 | **破冰启动**：刚好覆盖 1 次 AI 拍照识别消耗 |
  | **第 2 天** | **+8 pts** | 无 | **平稳成长**：递增微正反馈，强化习惯沉淀 |
  | **第 3 天** | **+15 pts** | 获得【欺骗餐护盾】×1 | **第一个关键里程碑**：15分够体验1次AI深度诊断，护盾防暴食 |
  | **第 4 天** | **+10 pts** | 无 | **稳步推进**：回归日常稳健节奏，持续覆盖拍照消耗 |
  | **第 5 天** | **+25 pts** | 获得【血清补签卡】×1 | **核心自救里程碑**：补签卡本身价值等同 50 积分，安全感爆棚 |
  | **第 6 天** | **+15 pts** | 无 | **冲刺前夜**：临门一脚，拉满对次日宝箱的心理期待 |
  | **第 7 天** | **+50 pts** | **开启金色神秘宝箱（含盲盒）** | **终极狂欢**：50分刚好可换1次单人补卡，宝箱开盲盒大奖，圆满收官 |

#### 2.2 火焰标识交互与「7天连击成长路线图」专属弹窗
* **触发入口**：首页顶部常驻徽章 `🔥 X天`。
* **交互体验**：点击右上角火焰徽章，弹出专属「🔥 7天连续自律里程碑挑战」成长路线看板：
  1. **连击荣耀头部**：展示当前连续自律天数（高亮大数字）、历史最高纪录徽章，以及今日达成状态（`✅ 今日已达成` / `⏳ 今日待打卡`）。
  2. **7天横向阶梯路线轨道 (Scrollable Track)**：
     - **已完成节点 (Completed)**：薄荷绿微光背景 + 绿色对勾 `✓`，标记已领取；
     - **今日节点 (Today)**：若已完成显示金色跳动火苗 🔥，若未完成显示呼吸发光环提示今日可领；
     - **未解锁节点 (Upcoming)**：半透明灰调胶囊 + 小锁扣 🔒；
     - **里程碑突出**：第 3 天（护盾）、第 5 天（补签卡）、第 7 天（金色宝箱）带有高亮徽标。
  3. **终极大奖条**：高光通栏展示“第7天终极奖励：+50 积分 + 金色宝箱”。
  4. **闭环行动按钮**：
     - 今日已打卡：显示浅色按钮 `[ 保持自律，明天继续 🔥 ]`，点击关闭；
     - 今日未打卡：显示高亮主按钮 `[ 立即记一餐，点亮今日火焰 📸 ]`，点击直达记餐流程，形成促活转化闭环。

#### 2.3 损失厌恶与断签挽救动线 (Loss Aversion & Recovery)
* **当日未打卡预警**：
  * 超过 20:00 未打卡，连击火苗变为闪烁红色预警：“⚠️ 今日未打卡，3天连击将在 24:00 清零重置！”
* **断签挽救弹窗 (The Streak Saver Modal)**：
  * 次日用户打开小程序若发现断签，弹窗提示：
    > *“你的 5 天连续打卡差点就断了！😱”*  
    > 选项 A：使用背包中的【血清补签卡】立即恢复（消耗道具）；  
    > 选项 B：扣除 50 契约积分拯救昨日连击；  
    > 选项 C：若无道具与积分，每周支持 1 次“分享给好友”免费拯救连击（兼顾裂变传播）。

#### 2.3 数据表设计与后端实现
在 `tb_user` 实体与新建 `tb_streak_record` 中增加如下字段：

```sql
-- 1. 用户主表补充连击字段
ALTER TABLE tb_user ADD COLUMN current_streak INT DEFAULT 0 COMMENT '当前连续打卡天数';
ALTER TABLE tb_user ADD COLUMN max_streak INT DEFAULT 0 COMMENT '历史最高连续打卡天数';
ALTER TABLE tb_user ADD COLUMN last_checkin_date DATE DEFAULT NULL COMMENT '最近一次打卡日期';
ALTER TABLE tb_user ADD COLUMN streak_freeze_count INT DEFAULT 1 COMMENT '可用补签卡数量';

-- 2. 连续打卡明细表
CREATE TABLE tb_streak_record (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    checkin_date DATE NOT NULL,
    streak_day INT NOT NULL COMMENT '第几天(1-7)',
    reward_points INT NOT NULL COMMENT '获得积分',
    item_reward VARCHAR(50) DEFAULT NULL COMMENT '掉落道具',
    is_makeup TINYINT(1) DEFAULT 0 COMMENT '是否为补签',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    KEY idx_user_date (user_id, checkin_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户连续打卡流水';
```

### 模块三：破除社交死锁 ——「官方公共自律营（一键匹配）」与「单人自律契约」

#### 3.1 现状痛点与解法
原 5 人私密对赌（`pages/team/team`）要求用户手动输入 6 位邀请码。散客用户因没有同样想减脂的朋友而完全被关在门外。
**破局解法**：保留熟人私密建队的同时，新增**“官方 7 天公共自律营”**与**“单人契约”**双通道！

#### 3.2 官方 7 天自律挑战营（一键匹配系统）
1. **一键自动拼车组队**：
   * 散客点击【一键加入官方自律营】；
   * 系统自动将当日报名池中的散客以 5 人为一组匹配分配至 `Official_Team_XXXX`；
   * 每人扣除 100 契约分作为入场押金；
2. **虚拟陪跑搭子（AI 兜底保底机制）**：
   * 若报名散客不足 5 人，系统自动分派官方虚拟自律队友（如“晨跑小鹿”、“燕麦拿铁酱”），保证队伍 100% 能够顺利发车！
   * 虚拟队友拥有拟真打卡数据与性格设定，每日在固定时段打卡，并在聊天区互动，激活真实用户参与感。
3. **玩法全量贯通**：
   * 匹配成功后，散客即可直接体验完整的**战术道具店（护盾/补签）**、**卧底间谍局（指认诱惑者）**、**突击查岗（限时 30 分钟）**以及**次日早 08:00 瓜分违约金盲盒**！

#### 3.3 单人自律契约 Flag（面向私密控）
* **定位**：给不愿社交、专注个人减脂的用户提供确定性激励。
* **玩法模式**：
  * 用户向系统立下 7 天契约：
    * 挑战项：连续 7 天每日记录至少 2 餐，且每日总热量不超过 TDEE 目标。
    * 押金：质押 150 契约积分。
  * **结算规则**：
    * 7 天全勤通关：系统奖励 **返还 150 积分 + 额外发放 50 积分奖励 + 颁发「克己自律」荣誉金质勋章**。
    * 违约漏打卡：每日违约扣除 30 积分，进入平台公共奖池。

#### 4.2 顺势授权交互策略 (Natural Opt-in Moments)
严禁在用户进入小程序时粗暴弹窗请求权限，而是采用**“高爽感时刻顺势引导”**：
1. **拍照打卡成功后**：AI 营养诊断评分出炉时，弹窗附带选择框：
   * *“是否订阅今日晚餐防超标提醒？” [勾选并授权]*
2. **加入对赌小队后**：
   * *“是否开启队友突击查岗与扣分预警实时通知？” [立即开启]*
3. **喝水完成一次后**：
   * *“下一次补水在 2 小时后，需要提醒您吗？” [好呀]*

#### 4.3 后端调度架构改造
重构 `WaterReminderScheduler` 为统一调度服务 `com.shike.scheduler.UnifiedReminderScheduler`：
* `0 45 11 * * ?`：检索午餐未打卡且有订阅额度的用户批量下发；
* `0 0 18 * * ?`：检索晚餐未打卡用户下发；
* `0 30 21 * * ?`：检索小队成员中今日尚未打卡的用户下发紧急预警。

### 模块五：周度价值沉淀 ——「AI 燃脂周报」与自律里程碑勋章

#### 5.1 业务心理学背景
单纯每天看数字容易产生疲劳感。用户最强烈的长线心理诉求是**“看到我这一周的坚持带来的实质变化”**。周报能够将虚拟的数据转化为**巨大的具象化成就感**，形成牢固的沉没成本。

#### 5.2 周报核心内容板块（每周日晚 20:00 自动生成）
1. **核心燃脂总账本**：
   * 本周累计摄入 vs 目标预算；
   * 本周创造热量赤字总量（如：`-3850 kcal`）。
2. **具象化燃脂换算（直观冲击力）**：
   * *“你本周少摄入了相当于 **15 碗大米饭** 或 **8 块麦辣鸡翅** 的热量！”*
   * *“本周热量赤字累计消灭了 **1 斤纯脂肪**，离腹肌又近了一大步！”*
3. **AI 营养师深度诊断分析**：
   * 碳水、蛋白质、脂肪摄入比例合理度评分；
   * 本周最佳自律轻食日 vs 隐形油脂偏高警示餐。
4. **自律里程碑勋章系统 (Milestone Badges)**：
   * `🥇 黄金全勤周`：连续 7 天无遗漏打卡。
   * `🥗 控油大师`：连续 5 天选择清淡少油餐饮。
   * `💧 水分充沛`：连续 7 天饮水达标 2000ml。
   * `🔥 燃脂先锋`：单周热量赤字突破 3000 kcal。

#### 5.3 朋友圈 / 小红书高级海报一键导出
* 基于 Canvas 2D 渲染高清磨砂拟态黑金周报卡片，带有用户的头像、昵称、连续打卡天数与成就勋章，右下角带有专属推荐小程序码。
* 既满足用户发圈炫耀的自尊心，又为小程序带来持续的精准自裂变新客。

### 模块六：轻量治愈陪伴 ——「自律生长微挂件」

#### 6.1 极简定位（区别于重型独立游戏）
无需开发庞大繁复的重型放置游戏，而是在首页以**轻盈灵动的动态挂件**形式呈现，与用户现实打卡深度联动：
* **未打卡状态**：小猫肚子咕咕叫，懒洋洋趴在小桌前等开饭；
* **轻食打卡后**：小猫大口享受新鲜沙拉，头顶飘出粉红爱心，弹出台词：*“哇！今天也是营养均衡的一天喵~🥗”*；
* **运动打卡后**：小猫戴上运动发带在跑轮上欢乐奔跑：*“燃脂大成功！卡路里在飞速蒸发喵！🏃”*；
* **饮水打卡后**：清凉水润波光微粒浮现，小猫吨吨吨喝水满足呼噜；
* **夜间深睡**：森林营地亮起微光，小猫钻进编织藤窝打呼噜（zZ）。

#### 6.2 情绪价值
将枯燥的“热量记账”转变为**“为了喂饱我的小猫、陪它一起健康变好”**的情感陪伴，有效解决工具类产品缺乏情感温度的顽疾。

### 模块七：AI 拍照识别「智能神评系统（扎心毒舌 vs 爽快夸夸 vs 动态变脸）」

#### 7.1 业务背景与改造成效
* **问题痛点**：传统热量记账工具（包含原有的「常见分量快速添加」卡片）交互冰冷枯燥，且挤占弹窗宝贵的垂直高度。用户对单纯的数字（675 kcal、蛋白质 32.6g）缺乏情感共鸣，记账 3 天后极易流失。
* **解决之道**：彻底废除低频鸡肋的静态食材胶囊，换装具备极高情绪价值与社交分享欲的**「AI 智能神评卡片 (`ai-critique-card`)」**。

#### 7.2 八大核心营养与行为判定引擎
系统结合用户**全天热量预算余额、餐品三大宏量营养素结构、当前时段以及手动调改行为**，0 毫秒即时判定：
1. **热量爆仓 (OVER_CAL, 🚨)**：`当日已摄入 + 本餐 > 目标热量 + 50kcal` ➡️ 扎心警报（如：*“吃得挺豪迈啊！这一顿直接干穿今天全天预算，晚饭你只配喝西北风了！”*）。
2. **碳水炸弹 (CARB_BOMB, 🌶️)**：碳水供能比 $> 58\%$ 或单餐碳水 $\ge 65g$ 且低蛋白 ➡️ 犀利毒舌（如：*“这满屏的碳水炸弹，你是准备吃饱了去冬眠吗？胰岛素已经在你血管里拉防空警报了！”*）。
3. **油脂超标 (HIGH_FAT, 🥑)**：脂肪供能比 $> 42\%$ 或脂肪绝对量 $\ge 30g$ ➡️ 调侃预警（如：*“这菜在油里游泳游得挺欢啊？吃完拿张吸油纸，能挤出半张葱油饼来。”*）。
4. **掉肌预警 (NO_PROTEIN, 🥩)**：总热量 $\ge 220kcal$ 但蛋白质 $< 10g$ ➡️ 严肃提醒（如：*“蛋白质就这么丁点？掉的全是辛苦攒的肌肉！代谢一降，喝凉水都长肉。”*）。
5. **深夜放毒 (LATE_NIGHT, 🌙)**：21:30 ~ 04:30 且热量 $\ge 180kcal$ ➡️ 扎心夜宵暴击（如：*“半夜放毒？脂肪最喜欢你这种自觉、热情且无私奉献的全自动培养皿了。”*）。
6. **封神模范 (GOD_TIER, 🏆)**：高蛋白（$\ge 22g$）+ 适中脂肪与碳水 + 合理热量 ➡️ 极致爽快夸奖（如：*“绝了！这蛋白质配比简直是教科书级别，腹肌在暗中给你疯狂鼓掌！”*）。
7. **干净自律 (CLEAN_EAT, ✨)**：低脂轻盈适度控卡 ➡️ 轻松夸夸（如：*“相当干净的一餐！没有乱七八糟的热量刺客，身体代谢表示极度舒适！”*）。
8. **当场听劝 (LISTENED, 💡)**：用户在弹窗中调减克数或删除高危食材使热量下降 $\ge 70kcal$ ➡️ 傲娇反转（如：*“算你识相！手起刀落砍掉多余热量，听劝的人才配拥有马甲线！”*）。

#### 7.3 86 条精选犀利神评库与交互亮点
* **海量语料储备**：全库涵盖 86 条精选神评，文风紧跟中文互联网青年语境，直击痛点，爆梗不断，几乎杜绝重复；
* **0 毫秒动态变脸**：全前端实时响应计算，不增加额外网络请求与 Token 消耗。用户修改克数时即时反转，交互拟真感极强。

## 4. 核心指标与留存提升预期目标 (KPI Target)

1. **次日留存率 (D1 Retention)**：由当前预估的 $\approx 15\%$ 提升至 **$35\% \sim 40\%$**；
2. **7 日留存率 (D7 Retention)**：由当前预估的 $\approx 8\%$ 提升至 **$22\% \sim 28\%$**；
3. **日均启动频次 (Daily Sessions)**：由 $1.2$ 次/天 提升至 **$3.5$ 次/天**（早餐、午餐、晚餐、睡前打卡）；
4. **小队对赌参与渗透率**：散客参与率从原本不足 $5\%$ 提升至 **$60\%+$**。
