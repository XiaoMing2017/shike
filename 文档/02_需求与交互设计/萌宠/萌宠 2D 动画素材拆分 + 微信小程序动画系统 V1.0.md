# 萌宠 2D 动画素材拆分 + 微信小程序动画系统 V1.0

**版本：V1.0**  
**平台：微信小程序**  
**目标：打造具有“生命感”的 2D 萌宠动画系统**

---

# 一、项目目标

本系统不是单纯播放 GIF 或逐帧动画，而是采用：

> **2D 分层素材 + 骨骼/关节式动画 + 状态机 + 程序随机行为**

让宠物具备类似真实动物的动态表现。

核心目标：

- 宠物可以自主活动
- 四肢可以独立运动
- 身体可以独立呼吸
- 尾巴可以独立摆动
- 耳朵可以独立变化
- 头部可以独立转动
- 眼睛可以眨眼
- 宠物可以自主走路
- 可以随机停下、观察、跳跃、趴下、睡觉
- 不需要玩家操作时，也不会完全静止
- 不同宠物拥有不同动作概率和行为习惯

最终达到：

> **玩家不是在看一个动画，而是在看一只“活着的小动物”。**

# 三、核心设计原则

## 3.1 不建议把宠物做成一张完整图片

错误方式：

```text
┌─────────────────┐
│                 │
│       🐱        │
│                 │
└─────────────────┘
```

整只猫作为一张 PNG。

这种方式只能：

- 整体移动
- 整体缩放
- 整体旋转

无法实现：

- 四肢独立运动
- 尾巴摆动
- 耳朵变化
- 头部转动
- 身体呼吸
- 脚掌落地
- 跳跃时身体压缩

因此不推荐。

宠物应该拆成多个独立 PNG。

以一只猫为例：

```text

├── body.png              身体
├── head.png              头
├── face.png              脸部
│
├── ear_L.png             左耳
├── ear_R.png             右耳
│
├── eye_L.png             左眼
├── eye_R.png             右眼
│
├── front_leg_L.png       左前腿
├── front_leg_R.png       右前腿
│
├── back_leg_L.png        左后腿
├── back_leg_R.png        右后腿
│
├── tail.png              尾巴
│
├── paw_L.png             左脚掌
├── paw_R.png             右脚掌
│
└── shadow.png            地面阴影
```



这样才能做真正的走路动画。

# 八、每个素材必须设置“锚点”

这是整个动画系统非常重要的一点。

例如：

```text
front_leg_L.png
```

不能简单以图片左上角作为旋转中心。

应该设置：

```text
      肩膀 ●
           │
           │
           │
           │
           ●
```

旋转中心：

> 肩膀关节

后腿：

> 髋关节

尾巴：

> 尾巴根部

耳朵：

> 耳根

头：

> 脖子连接位置

# 十、动画系统

动画系统分成两类。

## A. 基础循环动画

持续运行。

包括：

- 呼吸
- 尾巴摆动
- 耳朵微动
- 眼睛眨眼
- 身体轻微晃动

## B. 行为动画

根据 AI 状态触发。

包括：

- 走路
- 跑步
- 跳跃
- 坐下
- 趴下
- 睡觉
- 伸懒腰
- 左右观察
- 吃东西
- 玩耍

---

# 十一、生命感的核心：不要让所有动画同时播放

例如：

错误：

```text
呼吸
+ 尾巴摆动
+ 耳朵抖
+ 眼睛眨
+ 头部转动
+ 四肢运动
```

全部同时进行。

结果：

> 很像一个“动画模型”。

正确方式：

```text
基础生命层
│
├── 呼吸
├── 偶尔眨眼
└── 尾巴微动

行为层
│
├── 走路
├── 观察
├── 跳跃
└── 睡觉

随机事件层
│
├── 耳朵突然动一下
├── 看向左边
├── 看向右边
└── 摇尾巴
```

三个系统相互独立。

# 十二、呼吸动画

呼吸是最重要的“活物感”之一。

推荐：

```text

1.00
↓
1.015
↓
1.025
↓
1.015
↓
1.00
```

周期：

> 2.5～4 秒

并且不能完全规律。

例如：

```text
2.8s
3.2s
2.6s
3.5s
```

随机变化。

# 十三、眨眼动画

不要固定每 3 秒眨一次。

推荐：

```text
正常
↓
眼睛缩小
↓
闭眼
↓
恢复
↓
随机等待
```

随机间隔：

```text
2.5～7 秒
```

偶尔可以：

```text
快速眨两下
```

例如：

```text
blink
↓
blink
```

这会明显增加生命感。

# 十四、尾巴动画

尾巴不要使用简单：

```text
左 → 右 → 左 → 右
```

应该：

```text
-5°
-2°
+4°
+9°
+5°
0°
-4°
```

并加入缓动。

推荐：

> Ease In Out / Sine

尾巴动作频率也应该随机。

# 十五、耳朵动画

耳朵可以成为非常重要的情绪表现。

例如：

### 正常

```text
耳朵：0°
```

### 好奇

```text
左耳：-8°
右耳：+5°
```

### 听到声音

```text
两只耳朵突然竖起
```

### 紧张

```text
耳朵向后
```

---

# 十六、眼睛动画

眼睛不要只有：

```text
睁眼
闭眼
```

可以增加：

```text
眼球左看
眼球右看
眼球上看
眼球下看
眨眼
慢眨
快速眨眼
```

例如：

```text
宠物站着不动

身体：
呼吸

眼睛：
→ 看左边

2秒

→ 看右边

3秒

→ 正常

突然：

眨眼
```

这种效果非常容易产生：

> “它刚才是不是在看我？”

的感觉。

---

# 十七、走路动画

四条腿独立。

推荐使用简化的步态循环：

```text
Frame 1

左前腿 → 前
右前腿 → 后

左后腿 → 后
右后腿 → 前


Frame 2

左前腿 → 中
右前腿 → 中

左后腿 → 中
右后腿 → 中


Frame 3

左前腿 → 后
右前腿 → 前

左后腿 → 前
右后腿 → 后
```

动画同时加入：

```text
身体上下轻微运动
头部轻微晃动
尾巴运动
```

这样会比单纯移动四条腿自然很多。

# 十八、走路时身体不能水平移动

错误：

```text
猫 ─────────────→
```

正确：

```text
      ↑
猫 ↗     ↘
   ↓
```

身体应该有：

```text
X：向前
Y：轻微上下
Rotation：轻微前后
```

例如：

```text
X += speed

Y:
0
-2
0
+1
0

Rotation:
-1°
+1°
-1°
+1°
```

```text

↓
起跳
↓
空中
↓
下降
↓
落地
↓
缓冲
↓

```

### 准备

```text

```

### 起跳






自然很多。

# 二十五、动画数据不要写死在代码里

不要：

```javascript
cat.x += 10;
cat.leg.rotation += 5;
```

大量写死。

推荐：

```javascript
playAnimation("walk");
```

动画定义：

```json
{
  "name": "walk",
  "duration": 800,
  "loop": true,
  "tracks": [
    {
      "target": "frontLegL",
      "property": "rotation",
      "keyframes": [
        { "time": 0, "value": -20 },
        { "time": 400, "value": 20 },
        { "time": 800, "value": -20 }
      ]
    }
  ]
}
```

这样以后增加：

```text
狗
猫
兔子
仓鼠
龙
狐狸
```

只需要更换配置。

# 二十六、动画插值

不能直接瞬间改变：

```text
rotation = 20
```

需要：

```text
startValue
↓
interpolation
↓
endValue
```

例如：

```javascript
value =
start +
(end - start) * progress;
```

再加入：

```text
EaseIn
EaseOut
EaseInOut
Sine
Back
```

# 三十二、动作过渡

每个动作都需要 Transition。

例如：

```text

```

需要：

```text

↓

↓

↓
```

```text

↓
```

# 三十三、生命感增强机制

V1.0 可以增加一个：

> **Micro Behavior 微动作系统**

它不改变主要状态，只负责随机小动作。

例如宠物：

```text

```

后台随机触发：

```text

耳朵动一下
尾巴动一下
头轻微偏转

```

因此即使：

```text

```

玩家依然会觉得：

> “它是活的。”

> “播放一组宠物动画。”

> **“用动画系统模拟一只宠物。”**

例如玩家打开小程序：

```text
0秒

猫正在睡觉

↓

5秒

耳朵动了一下

↓

8秒

猫睁开眼睛

↓

看向玩家

↓

站起来

↓

伸懒腰

↓

走到沙发边

↓

跳下来

↓

在地毯上走两圈

↓

坐下

↓

舔一下爪子

↓

看向另一边

↓

趴下

↓

继续睡觉
```

玩家没有点击任何东西。

但宠物一直在：

> **自主生活。**

这才是整个萌宠系统真正的核心体验。

# 四十、V1.0 验收标准

完成后，一只宠物必须满足：

- [ ] 身体可以独立缩放
- [ ] 头部可以独立旋转
- [ ] 四条腿可以独立旋转
- [ ] 尾巴可以独立运动
- [ ] 耳朵可以独立运动
- [ ] 眼睛可以独立眨动
- [ ] 可以实现呼吸
- [ ] 可以自主走路
- [ ] 可以自主停止
- [ ] 可以随机观察
- [ ] 可以随机触发微动作
- [ ] 动作之间存在自然过渡
- [ ] 行为不会完全按照固定顺序循环
- [ ] Canvas运行稳定
- [ ] 宠物长时间运行不会明显卡顿

# 四十一、最终技术路线

```text
                    【萌宠】
                       │
                 2D PNG 分层素材
                       │
                       ↓
                  Anchor 锚点
                       │
                       ↓
                 Canvas 2D 渲染
                       │
             ┌─────────┴─────────┐
             ↓                   ↓
        Animation System      Behavior System
             │                   │
       ┌─────┼─────┐       ┌─────┼─────┐
       ↓     ↓     ↓       ↓     ↓     ↓
      身体   四肢   尾巴    Idle  Walk  Jump
      呼吸   头部   耳朵    Look  Sit   Sleep
       │     │     │       │     │     │
       └─────┴─────┴───────┴─────┴─────┘
                       │
                       ↓
                Micro Behavior
                       │
                       ↓
                  Random System
                       │
                       ↓
                “生命感”萌宠
```

**核心结论：**

> **美术不要画“动画”，而是提供“可运动的身体零件”。**
>
> **程序不要播放“整套动作”，而是控制这些身体零件。**
>
> 最终通过「骨骼/锚点 + 动画时间轴 + 状态机 + 随机微动作」组合出一只具有生命感的 2D 宠物。
